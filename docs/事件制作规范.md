# 事件制作规范

事件只在 `data/events.txt` 配置，不需要额外的 events_pool/event_pools 文件。文件编码为 UTF-8，每个事件一个 `{...}` 记录，记录可跨多行，末尾分号可省略。以 `#` 开头的整行是注释。

当前 `data/events.txt` 有九个事件：一层遗迹的「哈尼的考古队」「石台上的古剑」「地下温泉」「封印之门」「迷路的金哈尼」，以及全局的「圣女祭坛（沉睡的圣女）」「会说话的铠甲」「希露的究极兔子锅」「兰斯的旧债」。下文的「交换遗物」「荒野补给」等记录只是格式示例，不在游戏中。

## 格式

```text
{"事件名","标题","正文","图片","所属地图池","出现条件",
 "选项1说明","选项1指令",
 "选项2说明","选项2指令",
 "选项3说明","选项3指令"};
```

前六项顺序固定。此后每两项组成一个选项，不限制选项数量，至少填写一组。每项都用双引号包裹，包括空项 `""`。选项说明不能留空；指令留空表示离开。事件名是唯一识别名，不能重复，已使用的事件名应保持稳定以兼容入口存档。支持中文逗号及中文弯引号作为字段分隔符；字符串内部的引号请使用 JSON 转义 `\"`。

标题、正文、选项说明中的小写 `r` 全部转换为换行，`rr` 为段落空行；该规则不会处理事件识别名、图片路径、地图池和指令。英文说明中的普通字母 r 也会换行，编写时需注意。说明不会自动生成悬停解释。正文居中排版，建议用单个 `r` 手动断句，使每行不超过约27个汉字。

正文与选项说明可用四种括号标记文字，括号本身不显示：`【圣女之蛋】` 金色（物品、卡牌等名词）、`〔5%〕` 红色（代价）、`〈4〉` 蓝色（数量）、`〖……〗` 淡紫色并带水波起伏动画（刻文、低语、引语等）。水波文字从左到右逐字上浮约5像素再落下，每字间隔55毫秒，一轮2.6秒后重复（`scripts/event/event_wave_effect.gd`），例如 `「〖圣女们在此安眠，等待下一位主人。〗」`。例如 `失去〔5%〕最大生命，从〈4〉枚【圣女之蛋】中选择〈1〉枚。`。选项第一行固定为金色选项名，不解析标记。

## 界面与动画

事件页仿照《杀戮尖塔2》：深色底上，左侧为事件插画，经椭圆暗角与右侧渐隐融入背景；右侧一列依次为金色标题（`FormationArt.GOLD`）、居中白色正文、深青色斜角选项条。选项条第一行是金色选项名，第二行起是说明。标题、正文、结果和选项文字使用同一套文字样式（`EventOptionButton.add_shadow`）：3像素黑色描边（85%不透明）加一层浅黑色投影（偏移2像素、半透明）。

打开事件时不预先选中任何选项，所有选项条保持普通状态。鼠标移入的选项条变亮，出现蓝色发光描边并放大约2.5%，移出即恢复；鼠标会带走键盘焦点，因此同一时间只有一个选项亮起。使用键盘时，首次按方向键或Tab选中第一个可用选项，之后照常切换。遗物选择的物品卡采用同样规则。

右侧列固定在 x 900～1680、y 34～872，位于右下角部队HUD之上，**不使用滚动条**：标题、正文、全部选项和结果一次性显示。内容过多时按档位整体缩小字号、选项高度和间距（标题44→28、正文27→17、选项25→15），直到放得下；仍建议正文控制在8行、选项控制在5个以内，以免字号过小。

进入和离开事件都使用全局黑屏过渡（`ScreenTransition`：0.16秒淡到全黑，切换页面，0.2秒淡出）：地图问号节点经 `RunMapScreen._open_event`，控制台 `event` 经 `EventManager._mount`；点击「继续」后先淡到全黑再回到地图。若进入时已有黑屏过渡在进行（如继续游戏直接回到事件入口），事件页在这层黑屏下打开，不再重复淡入。

鼠标悬停（或键盘焦点）在选项上时，`EventOptionPreview` 从该选项已绑定变量的指令中找出提到的遗物与诅咒：`add relic`、`delet relic`、`choose relic`、`random relic` 列出的遗物显示为遗物说明框（`RelicTooltip`，名称加说明），`add curse` 的诅咒显示为诅咒卡（物品卡样式，1.2倍）。预览放在选项列左侧的插画区：遗物说明框竖排成一列，诅咒卡在说明框左边横排，垂直方向与选项对齐并限制在屏幕内；左侧放不下时诅咒卡改放到说明框下方或上方，保证互相不遮挡、也不遮挡选项。不可选的选项同样显示预览；选择选项或移开鼠标即隐藏。因此选项说明里不必再写遗物效果和诅咒效果。

打开事件时标题淡入；正文按总字数计算，前约80%直接显示，剩下约20%以每字约11毫秒的打字机效果出现（总时长0.08～0.32秒）。正文出现后，选项从左向右滑入并淡入，每个间隔55毫秒，单个约0.2秒。打字期间点击左键可立即显示全部正文。选择后其余选项隐藏，结果文字与“继续”选项条以同样动画出现。

图片可以填写 `res://assets/events/补给.png`、`assets/events/补给.png` 或 `补给.png`（默认从 `assets/events/` 查找）。支持现有其他 assets 路径。图片作为整个事件页的背景，等比缩放铺满窗口，不拉伸；宽高比不同时会裁去部分边缘。空图片使用默认主题图。指定的图片必须存在并可被 Godot 读取为纹理；新增图片后先让 Godot 完成导入。

建议背景按1920×1080（16:9）制作，也可使用2560×1440同等比例的大图。在1280×720窗口中会自动等比缩小。人物、遗迹或场景重点放在左侧约45%的区域（中心约在 x 540）；画面从屏幕宽度40%处开始向右渐隐，62%以右完全变为深色底，四周另有椭圆暗角（`shaders/event_art_fade.gdshader`）。图片文件不必手工缩成左侧小图，也不要把标题、选项或状态数值烘焙进图片。

事件页右下角沿用地图的原版HP血条、领队小卡、勋章和贝壳UI，并随奖励、治疗等变化更新；左上角不再额外列出这些文字数值。事件中的状态栏只展示信息，不开放部队编制入口。

## 地图池

| 层数 | 可填写的所属地图池 |
| --- | --- |
| 一层 | 一层荒野、一层遗迹 |
| 二层 | 二层利萨斯、二层自由都市、二层卡拉之森 |
| 三层 | 三层赫尔曼、三层JAPAN、三层赛斯 |
| 四层 | 四层魔界 |

池名也可附加“事件池”后缀，例如 `一层荒野事件池`。池为空时，事件可以在任意地图出现，仍需满足出现条件。当前每个事件填写一个所属池。

首次进入每层时，根据 `data/map.txt` 对应行的权重抽取主题并存档，事件与怪物均使用该主题的池，不会回退到其他主题池；未填写地图池的通用事件仍适用于所有主题。行军共四层，第三层后进入魔界，第四层首领击破后通关。旧存档保留已有主题、地图和节点入口；缺少主题的已进入楼层一至三层分别沿用荒野、利萨斯、赫尔曼，旧三层存档补上第四层地图。

## 出现条件与抽取

条件为空时不限制。支持 `hp>50`、`hp<50`、`gold>100`、`gold<100`，大小写不敏感，可在运算符两侧加空格。HP 使用进入节点时的当前生命 / 最大生命 × 100，阈值范围 0～100；gold 检测部队当前的贝壳数量，阈值为非负整数。比较严格采用大于、低于，等于阈值时不通过。可用 `&&` 连接多个条件，所有条件都通过才可出现。

```text
{"荒野补给","荒野补给","部队在路边发现了遗落的补给。rr先休息一下吧。","assets/battle/backgrounds/云间天光.png","一层荒野","hp<50 && gold<100","休整r恢复20%最大生命。","heal 20","继续",""};
```

进入问号且实际抽到事件时，先按地图池（包含通用事件）和当前条件筛选，再从本轮尚未出现的候选中随机抽取；所有当前合格候选都出现过后，只清除这些候选的本轮出现记录，再开始新一轮，随后每个候选仍只出现一次。暂不满足条件的事件保留原出现记录；未出现过的事件条件重新满足时仍有优先权。新周目清空出现历史。没有合格事件时显示可离开的空事件页，不会卡住节点。

事件在抽取并提交入口时标记为出现。进入后必须选择事件选项；不显示“返回地图”按钮，右键和共享ui_cancel均不能关闭或跳过事件。完成选择后点击“继续”结束节点，结果页也不接受右键跳过。入口快照保存主题、事件、出现历史和随机状态，继续游戏恢复同一个节点入口。选项中途不写入新存档，重新读档仍会回到选择前入口，这是现有入口存档规则。正常事件由出现条件与选项设计保证至少有一项可执行；控制台强制进入后即使所有选项不满足条件，也保持禁用，不额外提供退出选项。

## 选项指令

选项复用控制台的同一个命令分派入口，每次成功选择只执行一次。成功后选项禁用，显示结果，通过“继续”结束节点；右键不能结束。重新打开已选择事件不会再次执行。指令失败会显示错误，保留选择机会。打开商店、战斗或宝箱的指令先完成其界面，再回到事件结果页继续。

当前指令：`gold 正整数`、`add medal 正整数`、`add card 卡牌名`、`add relic 遗物名`、`add curse 诅咒名称`、`delet relic 遗物名`（也支持 `delete relic`）、`battle 怪物识别名`、`event 事件名`、`treasure 0|1|2|3`、`relic [遗物池名称]`、`shop`、`pay 正整数`（支付贝壳，不足时失败）、`heal 1～100`（恢复最大HP百分比，需在行军或强制事件中）、`hurt 1～99`（失去最大HP百分比，至少保留1点HP）、`maxhp 1～100`（最大HP增加百分比）、`choose relic 名称|名称|…`、`random relic 数量 名称|名称|…`，以及控制台 `help`。指令本身不将 r 当换行。

`add curse 诅咒名称` 获得 `data/curses.txt` 中定义的诅咒卡（诅咒是主人公阵营、HP与AT为0的物品卡，持有即生效，通常无法解除）。名称不存在时整组指令在执行前失败；已持有时不重复获得，但不算失败，同一选项的其他奖励照常发放。影响战斗的诅咒在战斗的「状态→诅咒」页显示。详见 [战斗状态窗口](战斗状态窗口.md)。

`maxhp 百分比` 永久提高部队HP增加率（`TroopState.max_hp_bonus`，随部队存档），因此最大HP按比例增加，当前HP同步增加相同数值；与其他HP增加率一起受部队加成上限约束。战斗中使用不改变本场已确定的HP上限。

`event 事件名` 按第一项唯一事件名直接打开指定事件，例如 `event 交换遗物`。无视地图池、层数、HP/金币出现条件和出现历史，可反复强制打开。也可以在标题界面使用；没有正在进行的部队时使用控制台调试部队。事件仍使用原本的选项、变量绑定和指令执行规则。退出强制事件回到原界面，不推进原地图节点，不覆盖入口存档，不写入正常抽取历史；选项获得的奖励、遗物交换和HP变化正常作用于当前部队。战斗、商店、宝箱或界面切换中需先结束当前界面。未知事件名或参数缺失会显示错误，保持当前界面不变。

同一选项可以用 `/` 分隔多条指令，从左到右执行，例如 `delet relic 加奈美忍法帖/add relic 妖怪宝具`。整组指令会先按顺序模拟检查遗物持有、遗物与卡牌存在、数值参数等，检查失败不开始删除或奖励。打开战斗、商店、宝箱的指令会等待其界面结束再执行后面的指令。若执行期间界面或数据发生改变而失败，已执行的指令不重复，结果页显示错误。事件战斗沿用当前HP，返回时保留损伤。

## 支付贝壳与战斗奖励

`pay 数量` 扣除贝壳。整组指令开始前会按顺序检查贝壳是否足够；事件进入时，选项中所有 `pay` 的合计超过当前贝壳的，该选项直接禁用并显示「贝壳不足」，其他选项照常可选。

`battle 怪物识别名` 后面的指令视为胜利奖励：只有战斗以「胜利」结束才会继续执行；败北或回合用尽时停止后续指令，结果页显示「战斗未获胜，后续奖励取消。」，选项仍算已选择。例如 `battle 哈尼考古队/relic` 只有打赢才开启遗物宝箱。

## 遗物选择与随机遗物

`choose relic 名称|名称|…` 打开遗物选择界面：列出的遗物中尚未持有的，以兰斯10原版物品卡（`assets/relics/item_card/`，神魔所属紫色框）展示，卡面为 `assets/cards/物品／图标名.png`（没有时使用遗物图标），羊皮纸区显示遗物说明（左对齐白字加深棕描边，仿原版物品卡，`RelicCard` 统一用于遗物选择、诅咒卡等全部物品卡）、黑色名条显示名称。卡牌依次从下方弹入；悬停或焦点时上浮并显示金色光晕；点选后其他卡淡出、所选遗物飞入遗物栏。事件中的选择必须完成，右键不关闭；控制台直接使用时右键可取消。

`random relic 数量 名称|名称|…` 从列出的未持有遗物中随机获得不超过数量的遗物（使用本节点随机状态）。两个指令都会在整组指令开始前检查遗物名称是否存在；列出的遗物全部已持有时不报错，显示“没有可获得的遗物。”，以免事件无法完成。`hurt` 按最大HP计算并四舍五入，不会致死。

## 选项变量

| 变量 | 抽取来源 |
| --- | --- |
| `%友方随机遗物` | 玩家当前持有的遗物，包含商店遗物 |
| `%随机遗物` | 默认遗物池，沿用普通/罕见/稀有的50/33/17权重 |
| `%普通遗物` | 默认遗物池内稀有度1的遗物 |
| `%罕见遗物` | 默认遗物池内稀有度2的遗物 |
| `%稀有遗物` | 默认遗物池内稀有度3的遗物 |

默认池及指定稀有度的奖励均排除当前持有的遗物，沿用获得遗物不重复的规则。没有候选时，该选项显示原因并禁用，其他选项仍可选；当前稀有度3遗物为郁金香3号、平实柠檬、岩石花、守护神。

同一选项的说明和指令共享变量绑定；同一变量出现任意多次都替换为同一个名称。不同变量分别抽取，不同选项使用各自的绑定。同一种变量在不同选项中优先抽不同对象，候选耗尽后才开始下一轮复用；只有一个候选时会复用。所有选项在事件节点进入时一次解析，说明显示的对象与实际命令对象一致；名称插入后不会再次把名称里的 r 转换为换行。绑定后的文本、命令与变量表一起写进入口快照，返回、重新打开和继续游戏都保持一致。

# 事件制作规范

事件只在 `data/events.txt` 配置，不需要额外的 events_pool/event_pools 文件。文件编码为 UTF-8，每个事件一个 `{...}` 记录，记录可跨多行，末尾分号可省略。以 `#` 开头的整行是注释。

## 格式

```text
{"事件名","标题","正文","图片","所属地图池","出现条件",
 "选项1说明","选项1指令",
 "选项2说明","选项2指令",
 "选项3说明","选项3指令"};
```

前六项顺序固定。此后每两项组成一个选项，不限制选项数量，至少填写一组。每项都用双引号包裹，包括空项 `""`。选项说明不能留空；指令留空表示离开。事件名是唯一识别名，不能重复，已使用的事件名应保持稳定以兼容入口存档。支持中文逗号及中文弯引号作为字段分隔符；字符串内部的引号请使用 JSON 转义 `\"`。

标题、正文、选项说明中的小写 `r` 全部转换为换行，`rr` 为段落空行；该规则不会处理事件识别名、图片路径、地图池和指令。英文说明中的普通字母 r 也会换行，编写时需注意。说明不会自动生成悬停解释。选项第一行显示金色，其余行显示浅色。右侧内容超过高度时可滚动，支持键盘焦点跟随。

图片可以填写 `res://assets/events/补给.png`、`assets/events/补给.png` 或 `补给.png`（默认从 `assets/events/` 查找）。支持现有其他 assets 路径。图片作为整个事件页的背景，等比缩放铺满窗口，不拉伸；宽高比不同时会裁去部分边缘。空图片使用默认主题图。指定的图片必须存在并可被 Godot 读取为纹理；新增图片后先让 Godot 完成导入。

建议背景按1920×1080（16:9）制作，也可使用2560×1440同等比例的大图。在1280×720窗口中会自动等比缩小。人物、遗迹或场景重点放在左侧约45%的区域；右半部留出较平缓的背景供标题、正文和选项阅读，底部约206逻辑像素避免放必须看清的内容。文字区另有半透明暗底。图片文件不必手工缩成左侧小图，也不要把标题、选项或状态数值烘焙进图片。

事件页右下角沿用地图的原版HP血条、领队小卡、勋章和贝壳UI，并随奖励、治疗等变化更新；左上角不再额外列出这些文字数值。事件中的状态栏只展示信息，不开放部队编制入口。

## 地图池

| 层数 | 可填写的所属地图池 |
| --- | --- |
| 一层 | 一层荒野、一层遗迹 |
| 二层 | 二层利萨斯、二层自由都市、二层卡拉之森 |
| 三层 | 三层赫尔曼、三层JAPAN、三层赛斯 |
| 四层 | 四层魔界 |

池名也可附加“事件池”后缀，例如 `一层荒野事件池`。池为空时，事件可以在任意地图出现，仍需满足出现条件。当前每个事件填写一个所属池。

新周目的每一层按种子选定一个对应主题并保存在地图中，事件与怪物均使用该主题的池。旧存档未记录主题时，一至三层默认荒野、利萨斯、赫尔曼。当前行军仍为三层；四层魔界已支持事件数据归属，待四层流程接入后使用。

## 出现条件与抽取

条件为空时不限制。支持 `hp>50`、`hp<50`、`gold>100`、`gold<100`，大小写不敏感，可在运算符两侧加空格。HP 使用进入节点时的当前生命 / 最大生命 × 100，阈值范围 0～100；gold 检测部队当前的贝壳数量，阈值为非负整数。比较严格采用大于、低于，等于阈值时不通过。可用 `&&` 连接多个条件，所有条件都通过才可出现。

```text
{"荒野补给","荒野补给","部队在路边发现了遗落的补给。rr先休息一下吧。","assets/battle/backgrounds/云间天光.png","一层荒野","hp<50 && gold<100","休整r恢复20%最大生命。","heal 20","继续行军",""};
```

进入问号且实际抽到事件时，先按地图池（包含通用事件）和当前条件筛选，再从本轮尚未出现的候选中随机抽取；所有当前合格候选都出现过后，只清除这些候选的本轮出现记录，再开始新一轮，随后每个候选仍只出现一次。暂不满足条件的事件保留原出现记录；未出现过的事件条件重新满足时仍有优先权。新周目清空出现历史。没有合格事件时显示可离开的空事件页，不会卡住节点。

事件在抽取并提交入口时标记为出现。进入后必须选择事件选项；不显示“返回地图”按钮，右键和共享ui_cancel均不能关闭或跳过事件。完成选择后点击“继续行军”结束节点，结果页也不接受右键跳过。入口快照保存主题、事件、出现历史和随机状态，继续游戏恢复同一个节点入口。选项中途不写入新存档，重新读档仍会回到选择前入口，这是现有入口存档规则。正常事件由出现条件与选项设计保证至少有一项可执行；控制台强制进入后即使所有选项不满足条件，也保持禁用，不额外提供退出选项。

## 选项指令

选项复用控制台的同一个命令分派入口，每次成功选择只执行一次。成功后选项禁用，显示结果，通过“继续行军”结束节点；右键不能结束。重新打开已选择事件不会再次执行。指令失败会显示错误，保留选择机会。打开商店、战斗或宝箱的指令先完成其界面，再回到事件结果页继续行军。

当前指令：`gold 正整数`、`add medal 正整数`、`add card 卡牌名`、`add relic 遗物名`、`delet relic 遗物名`（也支持 `delete relic`）、`battle 怪物识别名`、`event 事件名`、`treasure 0|1|2|3`、`relic [遗物池名称]`、`shop`、`heal 1～100`（恢复最大HP百分比，需在行军或强制事件中），以及控制台 `help`。指令本身不将 r 当换行。

`event 事件名` 按第一项唯一事件名直接打开指定事件，例如 `event 交换遗物`。无视地图池、层数、HP/金币出现条件和出现历史，可反复强制打开。也可以在标题界面使用；没有正在进行的部队时使用控制台调试部队。事件仍使用原本的选项、变量绑定和指令执行规则。退出强制事件回到原界面，不推进原地图节点，不覆盖入口存档，不写入正常抽取历史；选项获得的奖励、遗物交换和HP变化正常作用于当前部队。战斗、商店、宝箱或界面切换中需先结束当前界面。未知事件名或参数缺失会显示错误，保持当前界面不变。

同一选项可以用 `/` 分隔多条指令，从左到右执行，例如 `delet relic 加奈美忍法帖/add relic 妖怪宝具`。整组指令会先按顺序模拟检查遗物持有、遗物与卡牌存在、数值参数等，检查失败不开始删除或奖励。打开战斗、商店、宝箱的指令会等待其界面结束再执行后面的指令。若执行期间界面或数据发生改变而失败，已执行的指令不重复，结果页显示错误。事件战斗沿用当前HP，返回时保留损伤。

## 选项变量

| 变量 | 抽取来源 |
| --- | --- |
| `%友方随机遗物` | 玩家当前持有的遗物，包含商店遗物 |
| `%随机遗物` | 默认遗物池，沿用普通/罕见/稀有的50/33/17权重 |
| `%普通遗物` | 默认遗物池内稀有度1的遗物 |
| `%罕见遗物` | 默认遗物池内稀有度2的遗物 |
| `%稀有遗物` | 默认遗物池内稀有度3的遗物 |

默认池及指定稀有度的奖励均排除当前持有的遗物，沿用获得遗物不重复的规则。没有候选时，该选项显示原因并禁用，其他选项仍可选；当前尚无稀有度3遗物定义，因此 `%稀有遗物` 需先在 relics.txt 添加对应遗物才能可用。

同一选项的说明和指令共享变量绑定；同一变量出现任意多次都替换为同一个名称。不同变量分别抽取，不同选项使用各自的绑定。同一种变量在不同选项中优先抽不同对象，候选耗尽后才开始下一轮复用；只有一个候选时会复用。所有选项在事件节点进入时一次解析，说明显示的对象与实际命令对象一致；名称插入后不会再次把名称里的 r 转换为换行。绑定后的文本、命令与变量表一起写进入口快照，返回、重新打开和继续游戏都保持一致。

```text
{"交换遗物","交换遗物","旅行者想与你交换一件遗物。","","","",
 "用%友方随机遗物交换%随机遗物","delet relic %友方随机遗物/add relic %随机遗物",
 "用%友方随机遗物交换%随机遗物","delet relic %友方随机遗物/add relic %随机遗物",
 "拒绝交换r继续行军。",""};
```

事件系统脚本放在 `scripts/event/`，验证脚本、截图和日志统一放在工程外 `F:/RanceX Slay The Spire/test/events/`。事件选项只调用既有命令，不新增技能效果编号。

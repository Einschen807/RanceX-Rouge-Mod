# 卡牌、技能与共用部队编制

## 制作入口

所有卡牌只在 `data/cards.txt` 创建；所有技能只在 `data/skills.txt` 创建。UTF-8 文本，每条用 `{ ... };` 包裹并以分号结束。`#` 为整行注释，字符串使用双引号，可用 JSON 转义。不为人物创建单独的场景或脚本。

卡面统一放在 `assets/cards/`，必须208×312像素。卡面字段省略 `.png`，使用原素材名称；全角 `／` 是文件名字符。例如 `兰斯／基本.png`。不能把全角 `／` 改成目录分隔符 `/`。

当前启动样例覆盖十个阵营，并提供7张卡牌、14个技能用于测试全部异常，见 [异常测试卡牌](异常测试卡牌.md)。只选入能用当前基础效果执行的原版技能；没有将原版全部技能当作已完成的效果导入。任务中的三条卡牌示例保留其指定数值，配有当前可执行的样例技能。

## 卡牌记录：固定11字段

```text
{ "Lv42 兰斯", "兰斯", "兰斯／基本", 1, 0, 1, 20, 21, 50, 42, 1 };
```

顺序为：显示名、识别名、卡面、阵营、属性、性别、技能1、技能2、基础HP、基础AT、稀有度。

- 显示名唯一；识别名允许重复。程序通过 `catalog.find_name("Lv42 兰斯")` 精确定位，`catalog.find_identity("兰斯")` 返回所有同身份变体。
- 阵营1～10：主人公、利萨斯、赫尔曼、赛斯、自由都市、JAPAN、其他、亚人、怪物、神魔。
- 属性0～5：无、炎、冰、雷、光、暗。性别1～3：男、女、其他。稀有度1～3：普通、罕见、稀有。
- 技能ID为0表示该栏为空，否则必须存在。数值必须为非负整数。
- 成长星级是运行状态 `TroopState.levels`，默认0；名字中的 `Lv42` 是卡牌显示名的一部分，不能从名字推断成长等级。
- 升级卡牌是独立记录，显示名必须为原显示名追加一个半角 `+`，例如 `Lv42 兰斯+`。预览按完整显示名匹配，不按识别名匹配；缺少对应升级记录时显示原卡，已有 `+` 的卡牌保持自身。
- 百科每次打开自动读取所有有效的非 `+` 卡牌，不需要修改UI名单。升级记录通过部队编制的“查看升级”勾选框预览，不重复计入收藏数量。导出程序修改卡牌后须重新导出，数据被嵌入EXE。
- “查看升级”仅保存在 `TroopFormation` 界面中。卡面、名字、技能及数值使用升级记录预览，星级沿用实际卡牌；点击、拖动、部署、移除及战斗读取仍使用原始 `TroopState` 的实际卡牌。切换预览不写入持有名单、领队、星级或加成，关闭后再次打开默认取消勾选。

## 技能记录：固定18字段

```text
{ 20, "突击－零－", 1, 1, "", "", 0, 1, 100, 0, 0, 0, 0, 0, "", 0, 1, "攻击(1倍)" };
{ 33, "管家连击", 1, 1, "", "", 2, 1, 100, 2, 3, 0, 0, 0, "", 0, 3, "攻击(1倍)r3连击r本场战斗AP累计" };
```

顺序为：ID、名称、行动类型、技能类型、特效名、必杀技演出、AP/概率、效果1、数值1、效果2、数值2、效果3、数值3、是否自定义、发动条件、是否大招、AP类型、描述。

任务里的“燃烧剑”示例漏写了“是否自定义”的整数；正式格式必须补齐，不能把条件字符串误当作自定义开关。燃烧现在使用基础效果10，完整异常编号与编码见 [异常效果制作规范](异常效果制作规范.md)。

- 行动1主动；2标准回合开始自动；2000～2999作为特定自动事件的稳定事件编号，由战斗调用方传同一个 `auto_trigger`；3被动。被动不通过释放入口发动，未来持续效果由战斗消费方读取。
- 技能类型1～6：近战、远程、魔法、准备、恢复、特殊。自动/被动优先显示对应行动图标。
- 自动行动把AP字段解释为0～100的概率，不消耗AP、不占主动行动次数。
- 自定义、大招字段均为0或1。描述中的 `r` 换行；描述文本只展示，绝不反向解析成效果。
- 特效名填写原版文件名，例如 `"手里剑"`、`"魔法／暗魔法攻击"`（也接受 `.flat` 后缀），对应 `assets/effects/<特效名>/animation.json` 和同目录的 `audio.ogg`。空串按技能类型选择默认特效，不会因留空而缺失动画。不存在的名称会警告并回退默认特效。完整名称、默认规则和添加方法见 [技能特效说明](技能特效说明.md)。
- 必杀技演出是第6个字段，必须为双引号包裹的String。`""` 表示无演出；填写 `"兰斯必杀1"` 时查找 `assets/cut_ins/兰斯必杀1.tscn`，里克填写 `"里克必杀1"`，也接受 `.tscn` 后缀。演出在卡牌上抬后、技能特效前播放，播放速度固定，不受战斗倍速或“大招”开关影响，不参与数值结算。场景制作约定见 [必杀技演出说明](必杀技演出说明.md)。
- 旧17字段记录需在特效后补一个 `""`，不能直接混用；校验器会拒绝字段缺失或用数字填写演出栏位。

## 技能的三个核心文件

1. `data/skills.txt`：技能创建和组合，不写运行代码。
2. `scripts/skill_base_effects.gd`：编号基础效果、条件判断。当前0无效果、1伤害（100=1倍）、2连击（整数=攻击次数）、3治疗（100=1倍AT）、4本场AT增益（百分比）、10～23异常；异常的1～9为对方回合数，11～19为自身回合数。同种异常叠加，上限9。条件语法由 `battle_conditions.gd` 处理。新增编号先在 `has_effect` 注册，再补 `resolve`。
3. `scripts/skill_custom_effects.gd`：用技能ID分派特殊效果。返回追加命令，与基础效果同时存在。只执行一次，不放进连击循环。

通用生命周期放在 `skill_runtime.gd`，不要把AP规则复制到人物脚本。效果返回命令数组，由 `battle_state.gd` 实际应用。战斗与怪物数据规范见 [战斗与怪物制作规范](战斗与怪物制作规范.md)；抽取与存档业务尚未实现。

连击在读取三个槽后统一作用于效果编号1的倍率伤害命令，只重复攻击；其他基础命令和自定义命令执行一次。效果槽顺序不影响连击。无防御与增伤时，每击伤害为 `deployed_at × 数值 / 100`，保留浮点精度，由最终消费方取整。战斗播放层逐击播放技能特效，在每次命中帧单独扣血、增加1点Combo；AP、主动行动次数、技能使用次数及必杀演出按整次技能计算，不乘连击次数。

## AP与行动生命周期

`SkillRuntime`按卡牌显示名＋技能ID存储状态，同一识别名的不同卡牌不串状态。

| AP类型 | 使用后规则 | 战斗结束 | 换层/特殊重置 |
|---|---|---|---|
| 1 | 连续回合使用时基础AP+1，永不继续叠加；跳过该技能一次机会恢复 | 恢复 | 恢复 |
| 2 | 每用一次+1 | 保留 | 恢复 |
| 3 | 每用一次+1 | 恢复 | 恢复 |
| 4 | 限制一次 | 保留 | 恢复 |
| 5 | 本场限制一次 | 恢复 | 恢复 |

战斗调用 `begin_battle()`；新回合 `next_turn()`；战斗结束 `end_battle()`；换层或特殊事件 `reset_floor()`。主动技能通过 `use_skill(actor, skill, context)`，上下文包括可用`ap`、`deployed_at`和条件变量。检查`ok`后由调用方扣除返回的`ap_spent`并消费命令。每个角色每回合只允许一次主动行动，两个技能共享这个行动限制。释放失败不改状态。

## 数值和共享UI

HP和AT都采用 `基础值 × (1 + 0.12 × 星级)^2.5`。
领队出战值为 `实际值 × ox_coefficient + 同阵营其他卡牌实际值总和`，牛车系数默认5。阵营页签HP/AT始终统计该阵营全部可用卡牌，包含已上场领队。综合AT为 `全部阵营AT之和 ÷ 全部可用卡牌数量 × ox_coefficient`，与领队共用牛车系数，默认5，与领队选择和位置无关；没有卡牌时为0。综合HP仍为全部领队出战HP之和，再乘HP加成，不改变原公式。计算保留浮点，显示向下取整。

`scenes/troop_formation.tscn`是唯一编制界面。百科自动创建独立的`TroopState`，包含全部非 `+` 卡牌，默认7个领队位；实际游戏也实例化它，调用`configure(state)`传入自己的状态：

```gdscript
var catalog := CardCatalog.new()
if catalog.load_catalog():
    var state := TroopState.new()
    var owned: Array[String] = ["Lv42 兰斯"]
    state.configure(catalog, false, owned)
    var formation := preload("res://scenes/troop_formation.tscn").instantiate()
    formation.configure(state)
    add_child(formation)
```

不能为百科直接给真实存档发卡。真实抽取/奖励系统获得卡牌后更新传入的名单和模型；本次只提供这个接入点，不接管未实现的新游戏流程。

百科自由编制：点击下方卡牌部署；同阵营替换；七个位置满时需先下场。已部署卡牌再次点击不重复上场动画。点击领队选中其阵营；拖动使用实际卡牌的原尺寸视觉，放到其他领队位时交换或填入空位，放在阵营区域外的空隙时按卡牌中心就近吸附并播放位移动画，拖回下方阵营区域则下场。阵营中的领队卡牌显示原版Leader字样和蓝色呼吸光框，分别复用“卡牌／领队”和“卡牌／选择中”的FLAT素材及时间线。详情三态是共享卡牌视图的横向半翻转，不使用参考视频作为播放素材。成长星级由运行模型提供，界面默认0；内部预览方法不修改实际游戏进度。

部队编制按原版1920×1080的Pact坐标重建：上方七张208×312领队、十个阵营国旗页签、六列卡牌、右侧排序和统计。阵营按钮无领队时使用原版灰色背景，已有领队时金色，当前阵营使用升起的蓝色页签。数字来自原版字形图集，按钮保留原版FLAT悬停/按压状态和AIN规定的选中颜色。滚动条使用原版箭头、轨道和可拖动滑块。部队加成与部队编制使用原版图标，删除人物信息后紧邻排列；加成页使用原版卷轴、图标和页框。角色显示名白色，技能名称与成长星级数字使用黑色描边，五角星使用原版带黑边图标，AP数字在19×19圆形徽标中居中。

上方领队仅在按住并实际拖动时，卡牌透明度为55%；单击、悬停、焦点及松手后均保持正常透明度。拖动时原领队槽保留原版Not Set框，下方阵营中的领队卡牌仍为不透明。领队默认卡面底部只绘制AT信息及其背景，不绘制角色名称及名称背景。

部队加成去掉EXP强化、全物品强化、稀有运提升、穷追猛打。百科可选择AP最大值强化、AP恢复强化、更换领队、HP、物理/魔法增伤及全面强化，并用于当前测试战斗；其余项目待对应玩法落实再启用。抗性、必杀、连击当前基线0，尚无产生这些加成的效果，不填原版占位百分比。抢攻发生率和帮助按钮已移除。HP加成参与综合HP；物理/魔法增伤率在战斗按攻击类别应用，不无差别乘进综合AT。界面默认不添加悬浮说明，鼠标右键通过ui_cancel统一返回上一级。

## 验证与目录约束

技能名称与星级数字显式引用`assets/fonts/card_text.tres`，使用内嵌矢量黑体和加粗参数，不继承标题页的SystemFont。技能名称18号字、黑色描边宽度8；星级数字21号字、黑色描边宽度7。Godot的描边参数经过窗口缩放后会变薄，不能只通过读取参数确认效果。字体样式改动必须从标题页点击百科卡牌入口截图检查，独立加载编制场景的默认主题与实际入口可能不同。测试预览入口为项目外`test/render_skill_outline.gd`，覆盖三个详情状态。

校验器拒绝重复显示名/技能ID、非整数、缺少技能、未注册效果/条件、错误卡面尺寸和缺少分号。失败时整个数据库不投入运行，页面明确展示加载错误。

自动测试入口是项目外 `F:/RanceX Slay The Spire/test/run_formation_tests.gd`，截图/报告在 `test/formation`，日志在 `test/logs`，素材来源清单在 `test/resource_sources`。不得把测试代码或输出迁入Rance。导出预设要包含`data/*.txt`。保留所有`.uid`、`.import`和动画JSON；不推送GitHub。

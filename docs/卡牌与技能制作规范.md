# 卡牌、技能与共用部队编制

## 制作入口

未来新增效果前，先询问用户应采用通用基础效果编号还是自定义接口，再实施。独立特殊效果通过技能ID在代码中实现，详见[护盾与自定义技能](护盾与自定义技能.md)。

所有卡牌只在 `data/cards.txt` 创建；所有技能只在 `data/skills.txt` 创建。UTF-8 文本，每条用 `{ ... };` 包裹并以分号结束。`#` 为整行注释，字符串使用双引号，可用 JSON 转义。不为人物创建单独的场景或脚本。

卡面统一放在 `assets/cards/`，必须208×312像素。卡面字段省略 `.png`，使用原素材名称；全角 `／` 是文件名字符。例如 `兰斯／基本.png`。不能把全角 `／` 改成目录分隔符 `/`。

原版全部1,135张卡面已存入该目录，按原图逐字节保留，包括65张原名以 `_卡牌／` 开头的版本。普通原名去掉 `卡牌／` 前缀，例如 `卡牌／兰斯／基本.ajp` 对应 `兰斯／基本.png`；带下划线版本去掉 `_卡牌／` 后保留一个前导 `_`，例如 `_卡牌／ＫＤ／基本.ajp` 对应 `_ＫＤ／基本.png`，与普通版本独立共存。现有34张卡面及其导入设置保留不变。卡面入库不自动创建卡牌或技能，新增可用卡牌仍在 `data/cards.txt` 配置。来源与文件校验清单保存在工程外 `test/card_portraits_all/`。

现有卡牌包含《卡牌设计.txt》的32组、《卡牌设计2.txt》的9组、《卡牌设计3.txt》的12组及《卡牌设计4.txt》新增的26组，普通版与强化版共158张，覆盖十个阵营；旧卡牌与测试卡牌已从卡牌库删除。接入能力叠加、额外施放、领队被动、多属性、随机DOWN替身、贝壳联动、条件附加异常、末位领队行动及击杀成长等实际效果；详见[卡牌设计实现](卡牌设计实现.md)、[卡牌设计2实现](卡牌设计2实现.md)和[卡牌设计3实现](卡牌设计3实现.md)。未将原版全部技能当作已完成效果导入。

## 卡牌记录：固定12字段

```text
{ "Lv42 兰斯", "兰斯", "兰斯／基本", 1, 0, 1, 20, 21, 50, 50, 1, 0 };
```

顺序为：显示名、识别名、卡面、阵营、属性、性别、技能1、技能2、基础HP、基础AT、稀有度、是否裸卡。

是否裸卡：1 是、0 否，对应原版卡牌数据的「裸」标记。设置页「窗口 → 内容显示 → 和谐模式」勾选后（写入用户目录 settings.cfg 的 display/harmony_mode），裸卡在所有卡牌视图（编制、百科、战斗、商店、宝箱、地图小卡）改用 `assets/formation/censored_portrait.png`：深色马赛克底加红色禁止章（斜杠位于圆圈下层且不超出圆圈）、「和谐」与「已和谐」字样，阵营底框、名称和数值照常显示。卡面统一经 `CardCatalog.portrait_path()` 解析；切换设置后新打开的界面生效。当前所有卡牌均为 0。和谐卡面由工程外 `test/harmony_mode_20261023/make_censored_portrait.py` 生成。

普通版与强化版的基础HP和AT均按稀有度统一设置：其他阵营普通／罕见／稀有为50／75／100，神魔阵营为75／100／125。首次重复获取替换为强化版本，之后每次重复等级+5，保留等级、编制和技能运行状态，详见[卡牌强化规则](卡牌强化规则.md)。

- 显示名唯一；识别名允许重复。程序通过 `catalog.find_name("Lv42 兰斯")` 精确定位，`catalog.find_identity("兰斯")` 返回所有同身份变体。
- 阵营1～10：主人公、利萨斯、赫尔曼、赛斯、自由都市、JAPAN、其他、亚人、怪物、神魔。
- 属性0～5：无、炎、冰、雷、光、暗。性别1～3：男、女、其他。稀有度1～3：普通、罕见、稀有；稀有度0为事件专用，不进入宝箱或随机商店卡池。
- 技能ID为0表示该栏为空，否则必须存在。数值必须为非负整数。
- 成长星级是运行状态 `TroopState.levels`，默认0；名字中的 `Lv42` 是卡牌显示名的一部分，不能从名字推断成长等级。
- 升级卡牌是独立记录，显示名必须为原显示名追加一个半角 `+`，例如 `Lv42 兰斯+`。预览按完整显示名匹配，不按识别名匹配；缺少对应升级记录时显示原卡，已有 `+` 的卡牌保持自身。
- 百科每次打开自动读取所有有效的非 `+` 卡牌，不需要修改UI名单。升级记录通过部队编制的“查看升级”勾选框预览，不重复计入收藏数量。导出程序修改卡牌后须重新导出，数据被嵌入EXE。
- “查看升级”是部队编制和宝箱选卡界面的显示状态。卡面、名字、技能及数值使用升级记录预览，星级沿用实际卡牌；点击、拖动、部署、移除及战斗读取仍使用原始 `TroopState` 的实际卡牌。切换预览不写入持有名单、领队、星级或加成，关闭后再次打开默认取消勾选。
- 升级预览通过 `scripts/card/upgrade_preview_text.gd` 比较实际卡牌与强化记录，仅改动和新增的文字使用柔和亮绿 `#9fe47f`；数值按完整的整数或小数标绿，例如2→2.5标绿整个2.5、50→40标绿整个40，百分比将数字与%号一并标绿，例如5%→8%标绿整个8%；其余未变化的单位与上下文保持原色。差异标绿仅用于技能描述正文；技能名称、AP、卡名及HP/AT数字均保持原有颜色。关闭预览或原卡本身已强化时不留下差异颜色。

## 技能记录：固定18字段

```text
{ 20, "突击－零－", 1, 1, "", "", 0, 1, 100, 0, 0, 0, 0, 0, "", 0, 1, "攻击(1倍)" };
{ 33, "管家连击", 1, 1, "", "", 2, 1, 100, 2, 3, 0, 0, 0, "", 0, 3, "攻击(1倍)r3连击r本场战斗AP累计" };
```

顺序为：ID、名称、行动类型、技能类型、特效名、必杀技演出、AP/概率、效果1、数值1、效果2、数值2、效果3、数值3、是否自定义、发动条件、是否大招、AP类型、描述。

发动条件与怪物行为共用[技能与怪物条件规范](技能与怪物条件规范.md)。例如 `"AP2以上 && (COMBO0 | 敌方异常存在<燃烧>)"`；友方固定指玩家，敌方固定指怪物，`&&`为与、`|`为或、`()`优先。以上、以下均包含边界，AP在扣费前判定。

任务里的“燃烧剑”示例漏写了“是否自定义”的整数；正式格式必须补齐，不能把条件字符串误当作自定义开关。燃烧现在使用基础效果10，完整异常编号与编码见 [异常效果制作规范](异常效果制作规范.md)。

- 行动1主动；2标准回合开始自动；2000～2999作为特定自动事件的稳定事件编号，由战斗调用方传同一个 `auto_trigger`；3被动。被动不通过释放入口发动，支援持续效果由 `BattleSupports` 读取。
- 技能类型1～7：近战、远程、魔法、准备、恢复、特殊、能力。编号7为“能力”；自动/被动优先显示对应行动图标。
- 能力技能用于在本场战斗中临时提供我方全局增益，通常将“是否自定义”设为1，并在 `SkillCustomEffects.resolve()` 中按技能ID实现。具体作用范围、叠加方式和持续规则由该技能代码决定；战斗临时数据归 `BattleState`，不得写入持久部队或周目状态。类型7本身不自动赋予增益，不会因为更改类型就获得额外效果；少量适合现有编号基础效果的能力仍可按需复用，不强制所有能力都自定义。本次新增类型不分配新的基础效果编号。
- 能力使用手工绘制的向上握拳图标：卡牌为 `assets/formation/skill_ability.png`（36×36，通常显示34×34），战斗普通预告为 `assets/battle/intent_7.png`（62×56），大招预告为 `intent_ultimate_7.png`（62×73）。拳头本体相对首版缩小约11%，居中并保留内边距；金色图案、黑底、金色边框保持原样。原 `skill_7.png` 为自动与普通被动行动图标，`skill_8.png` 专用于部队编制效果，两者不随技能类型编号重命名。
- 自动行动把AP字段解释为0～100的概率，不消耗AP、不占主动行动次数。
- 自定义、大招字段均为0或1。描述中的 `r` 换行；描述文本只展示，绝不反向解析成效果。
- 大招为1时，我方技能类型图标左上角沿上边和左边增加暗暖红色短折角边框，34像素图标的两条边各长12像素，完整收在图标及技能框内，不添加三角；卡牌总览、编制、技能详情和两种战斗操作模式保持一致，战斗中禁用的大招标记随之变暗。敌方预告使用对应类型的原版大图标，并叠加原版红框、红色菱形感叹号动画，释放预告动画仍保留标记。普通技能使用原图标。标识仅由大招字段决定，与必杀技演出及“必杀”临时增伤状态独立，不改变AP、伤害或使用次数。
- 卡牌AP圆形标记中的数值使用统一卡牌字体、关闭阴影和轮廓后居中显示；阵营属性圆框保留原素材尺寸，各属性图标按原素材圆形槽的位置嵌入，避免不同阵营装饰尺寸差异导致错位。
- 特效名填写原版文件名，例如 `"手里剑"`、`"魔法／暗魔法攻击"`（也接受 `.flat` 后缀），对应 `assets/effects/<特效名>/animation.json` 和同目录的 `audio.ogg`。空串按技能类型选择默认特效，不会因留空而缺失动画。不存在的名称会警告并回退默认特效。完整名称、默认规则和添加方法见 [技能特效说明](技能特效说明.md)。
- 必杀技演出是第6个字段，必须为双引号包裹的String。`""` 表示无演出；填写 `"兰斯必杀1"` 时查找 `assets/cut_ins/兰斯必杀1.tscn`，里克填写 `"里克必杀1"`，谦信填写 `"谦信必杀1"`；三者共用卡牌裂开展开的演出模板，也接受 `.tscn` 后缀。演出在卡牌上抬后、技能特效前播放，播放速度固定，不受战斗倍速或“大招”开关影响，不参与数值结算。场景制作约定见 [必杀技演出说明](必杀技演出说明.md)。
- 旧17字段记录需在特效后补一个 `""`，不能直接混用；校验器会拒绝字段缺失或用数字填写演出栏位。

## 技能的三个核心文件

1. `data/skills.txt`：技能创建和组合，不写运行代码。
2. `scripts/skill/skill_base_effects.gd`：编号基础效果、条件判断。0无效果、1伤害（100=1倍）、2连击（整数=攻击次数）、3恢复最大HP百分比、4失去最大HP百分比（3、4负数作用于对方）、5本方领队DOWN、6～9额外物理/魔法抗性与增伤、10～24异常（24为纯净）、25～29预留、30～34配置/解除支援、40玩家护盾、41怪物护盾（军师、结界、体质等使用自定义接口）。旧本场AT增益和AT倍率治疗为35、36。完整数值规则见 [支援与DOWN制作规范](支援与DOWN制作规范.md)。异常的1～9为对方回合数，11～19为自身回合数，同种叠加上限9；纯净的数值表示阻挡次数，不随回合减少。条件语法由 `battle_conditions.gd` 处理；新增编号先注册 `has_effect`，再补 `valid_value` 与 `resolve` 或持续读取。
3. `scripts/skill/skill_custom_effects.gd`：勾选自定义后，用技能ID分派特殊效果。主动/自动接口 `resolve` 返回追加命令，与基础效果同时存在，只执行一次，不放进连击循环；被动支援接口 `passive` 返回持续规则。军师、结界、体质、封锁与一次抵挡均使用此接口，TXT中的基础效果槽不再引用特殊编号。

通用生命周期放在 `skill_runtime.gd`，不要把AP规则复制到人物脚本。效果返回命令数组，由 `battle_state.gd` 实际应用。新增基础效果45～50及自定义分派见 [卡牌设计实现](卡牌设计实现.md)。战斗与怪物数据规范见 [战斗与怪物制作规范](战斗与怪物制作规范.md)。

连击在读取三个槽后统一作用于效果编号1的倍率伤害命令，只重复攻击；其他基础命令和自定义命令执行一次。效果槽顺序不影响连击。无防御与其他增伤时，我方每击伤害为 `deployed_at × 数值 / 100 × (1 + 已有Combo × 0.1)`，保留浮点精度，由最终消费方取整。Combo与强化、必杀等在额外增伤率内加算；每次命中后才增加1点Combo，零Combo的1倍2连击依次为1倍、1.1倍。战斗播放层逐击播放技能特效并单独扣血；AP、主动行动次数、技能使用次数及必杀演出按整次技能计算，不乘连击次数。

## AP与行动生命周期

`SkillRuntime`按卡牌显示名＋技能ID存储状态，同一识别名的不同卡牌不串状态。

所有卡牌界面通过 `SkillRuntime.display_state()` 读取当前技能费用及次数状态，包括编制、技能详情、战斗卡面、胜利领队及强化比较。AP累计增加后显示紫色数字，连续回合加费显示橙色，限制一次的技能用完仍显示费用数字，圆标切换为原版灰色“ＡＰ／已使用”，数字使用原版“幅１０／黑渐变”位图。强化预览按实际卡牌对应技能槽的计数显示强化后的费用，不修改运行状态；继承的一次性限制同样显示灰色圆标和黑色数字。胜利搜刮期间保留本场状态，离开战斗后再按下表清理；跨战斗累计和本局一次限制继续保留，换层或“重置卡牌状态”后恢复。

| AP类型 | 使用后规则 | 战斗结束 | 换层/特殊重置 |
|---|---|---|---|
| 1 | 连续回合使用时基础AP+1，永不继续叠加；跳过该技能一次机会恢复 | 恢复 | 恢复 |
| 2：AP累计 | 每用一次+1，跨战斗累计 | 保留 | 恢复 |
| 3：本局内AP累计 | 每用一次+1，仅当前战斗累计 | 恢复 | 恢复 |
| 4 | 限制一次 | 保留 | 恢复 |
| 5 | 本场限制一次 | 恢复 | 恢复 |

战斗调用 `begin_battle()`；新回合 `next_turn()`；战斗结束 `end_battle()`；换层或特殊事件 `reset_floor()`。主动技能通过 `use_skill(actor, skill, context)`，上下文包括可用`ap`、`deployed_at`和条件变量。检查`ok`后由调用方扣除返回的`ap_spent`并消费命令。每个角色每回合只允许一次主动行动，两个技能共享这个行动限制。释放失败不改状态。

## 数值和共享UI

HP和AT都采用 `基础值 × (1 + 0.12 × 星级)^2.5`。
领队出战值为 `实际值 × ox_coefficient + 同阵营其他卡牌实际值总和`，牛车系数默认5。阵营页签HP/AT始终统计该阵营全部可用卡牌，包含已上场领队。综合AT为 `全部阵营AT之和 ÷ 全部可用卡牌数量 × ox_coefficient`，与领队共用牛车系数，默认5，与领队选择和位置无关；没有卡牌时为0。综合HP仍为全部领队出战HP之和，再乘HP加成，不改变原公式。计算保留浮点，显示向下取整。

`scenes/troop_formation.tscn`是唯一编制界面。百科自动创建独立的`TroopState`，包含全部非 `+` 卡牌，默认7个领队位；实际游戏也实例化它，调用`configure(state)`传入自己的状态：

```gdscript
var catalog := CardCatalog.new()
if catalog.load_catalog():
    var state := TroopState.new()
    var owned: Array[String] = ["Lv42 兰斯"]
    state.configure(catalog, false, owned)
    var formation := preload("res://scenes/troop_formation.tscn").instantiate()
    formation.configure(state)
    add_child(formation)
```

不能为百科直接给真实存档发卡。真实抽取/奖励系统获得卡牌后更新传入的名单和模型；本次只提供这个接入点，不接管未实现的新游戏流程。

百科自由编制：点击下方卡牌部署；同阵营替换；七个位置满时需先下场。再次点击下方阵营列表中的已部署领队会下场，并以0.20秒快速移回该卡所在列表位置；点击上方领队仍只选择阵营。下场飞行期间避免重复操作，拖回列表沿用相同过渡。点击领队选中其阵营；拖动使用实际卡牌的原尺寸视觉，放到其他领队位时交换或填入空位，放在阵营区域外的空隙时按卡牌中心就近吸附并播放位移动画，拖回下方阵营区域则下场。阵营中的领队卡牌显示原版Leader字样和蓝色呼吸光框，分别复用“卡牌／领队”和“卡牌／选择中”的FLAT素材及时间线。上方领队行只高亮当前阵营对应的一张领队；当前阵营没有领队时全部不高亮，切换页签、详情或升级预览均沿用该规则。详情三态是共享卡牌视图的横向半翻转，不使用参考视频作为播放素材。成长星级由运行模型提供，界面默认0；内部预览方法不修改实际游戏进度。

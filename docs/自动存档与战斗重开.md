# 节点入口自动存档与战斗重开

一个周目只有一个系统自动存档，玩家不能自由存档、选择多个槽位或在战斗途中保存。每次进入一个新的根节点时，系统保存该节点的初始状态，之后的选择、行动、战斗结果和退出游戏都不覆盖这个入口。进入下一节点时才更新存档。

## 战斗重开：已接入

`BattleState.configure()`记录进入战斗准备时的快照；点击“战斗开始”之前再记录一次，将玩家在准备界面调整后的编制纳入本次战斗的重开基准。右上角“重开”立即读取这份战前快照，返回准备界面，不经过界面切换演出。

快照包含持有卡牌、七个领队的位置、卡牌星级、牛车系数、部队加成/点数、战前增伤与抗性、技能使用次数、双方随机数状态、怪物初始数据、HP/AP、预备异常/支援、行动预告和回合限制等。DOWN引起的自动换人、退场角色记录、伤害、局内增益和已用技能不会污染快照。恢复时更新原来的共享`TroopState`，所以战斗管理器和部队界面仍引用同一个编制对象。重开后的新战斗也以这份快照为基准，可重复重开。

`BattleCheckpoint`管理这份局部快照，`TroopCheckpoint`提供纯数据的编制/技能运行状态序列化。随机数的64位种子和状态使用字符串，阵营加成及异常编号使用显式记录，避免JSON数字精度和字典键转换造成变化。

DOWN替补在新回合标题后、玩家回合标识和自动行动前登场：使用原版完整卡牌，从下方200像素上移，保持1.2倍展示，再缩回1倍并淡出。原版时长为150/500/150毫秒，随战斗速度缩放。原卡在回合标题期间仍显示DOWN；替补展示至650毫秒时恢复正常卡槽。多个替补按位置依次演出。

## 节点自动存档：框架，尚未接入地图/事件

新增`RunAutosave`全局服务，不在初始化、测试战斗或百科界面自动读写存档。地图、事件和真实周目仍未制作，目前也没有新增标题“继续”功能；未来由节点路由器接入以下入口。

| 接口 | 调用时机与行为 |
|---|---|
| `begin_run(run_id, seed)` | 新周目初始化，设置周目ID和随机数种子；首次进入节点时才提交存档 |
| `enter_node(id, kind, initial_node, progress, troop)` | 进入根节点，先保存完整入口，再让玩家开始交互；一个已进入的节点不能再次覆盖入口 |
| `enter_subscene(kind, context)` | 节点内打开子界面或触发子战斗，压入内存上下文，不写文件 |
| `leave_subscene()` | 子流程结束，回到原节点，不写文件 |
| `finish_node()` | 节点完成，允许下一根节点进入；保留当前文件直到新入口成功提交 |
| `resume(troop)` | 读取入口，恢复编制与周目随机数，清空子流程，发出`entry_loaded`；路由器按节点类型重建初始界面 |
| `entry_snapshot()` | 返回快照副本供路由器读取，不提供保存功能 |

`initial_node`必须包含足以重新构建节点初始界面的纯数据，包括已生成的选项、奖励、目标怪物、节点内初始状态等；不能只保存节点类型而重新随机生成内容。`progress`保存进入节点前的周目状态：路线、物品、货币、事件标志、角色状态等。当前未实现的这些系统未来按各自数据模型填写。数据仅允许字符串键的字典、数组、字符串、布尔值、有限数值和null；不保存场景节点、资源对象或实时动画。

战斗根节点的`initial_node`可以保存`BattleCheckpoint.capture(preparation)`的结果，读档后用`BattleCheckpoint.restore`重建准备状态。节点存档记录的是**刚进入节点时**的准备界面；局部“重开”记录的是**点击战斗开始前**最后确认的编制，两者有各自的边界。

### 节点示例

- 战斗节点：进入准备界面时保存。战斗一半退出，继续时恢复进入节点的准备界面。
- 事件节点：生成并保存事件选择界面后开始交互。选A离开则完成节点；选B开启战斗则调用`enter_subscene("battle", ...)`，这场战斗没有新的根节点存档。战斗中退出，继续仍回到原事件选择界面。子战斗结束先退出子流程，再决定事件是否完成。
- 恢复点、状态节点等：保存操作前的入口状态。操作中退出，继续回到该入口；操作完成并进入下一节点后，才保存操作结果形成的新入口。

### 文件与失败处理

唯一活动存档为`user://run_checkpoint.json`，包含版本1、周目ID、周目随机数、节点类型/ID/初始数据、周目进度和编制。不存在玩家手动存档API或槽位选择界面。`.tmp`用于完整写入，`.bak`是系统损坏恢复副本，不能作为第二个存档槽选择。

写入先完成临时文件并flush，再保留旧的有效文件，最后提交新文件；写入失败不推进内存中的节点入口。主文件损坏时允许读取最后的完整备份；比当前程序更新的版本直接拒绝读取，避免回滚到旧备份。每次恢复前校验数据库引用、编制、技能次数和数据结构。首次版本尚无历史存档，后续格式变化必须增加迁移规则，不能直接静默接受旧版本。

本轮仅搭建框架并做编译检查；按用户要求，不执行其文件读写、退出重进或节点流程测试。真实节点和“继续游戏”接入后再验证这些流程。

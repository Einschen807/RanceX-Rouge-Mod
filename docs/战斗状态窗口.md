# 战斗状态窗口

「重开」按钮位于右上角（1832,16）；「状态」「解析」并排放在右下角「结束该轮」上方（1744,890 和 1832,890），统一使用 80×80 原版方框、图标加文字排版、字号和交互状态。领队旁不再显示原先的大状态按钮。既有原始图片、动画 JSON、导入设置和脚本 UID 保持完整。

支援上限仍为 7 个。支援条保持原生大小和原位置，友方外沿为 x=1893，以 70 像素间距从血条上方向上排列；满 7 个时顶端为 16 像素，底端约 502 像素。出现第七个我方支援时，重开按钮自动放在该支援左侧，间隔12像素（1551,16）；支援减少后恢复右上角（1832,16）。增减支援和重开恢复时都会立即重新布局。重开按钮高于支援动画，保持可见且可点击。

双方支援持续回合数字沿用原版圆圈与数字图集，按圆圈的中心对齐，留2像素内边距；两位数字自动等比缩小，保持在圆内。

解析面板位于左侧（1920×1080 基准坐标 458,16），状态面板位于右侧（1150,16）。两者保留 392×420 的内部布局，共同缩放到80%，实际显示为313.6×336；底端为352像素，避开下方怪物技能行为及其放大动画。金框、透明底色、着色器与内部文字一起缩放。状态面板可切换「能力」「诅咒」两页，列表展示名称和说明，内容较长时可滚动。

两侧面板可同时打开，不遮暗全屏、不阻挡战斗操作；出牌和结束回合时保持显示，能力结算后即时更新。再次点击状态按钮可以关闭；Esc 或鼠标右键优先关闭临时弹窗，然后关闭状态、解析面板，焦点回到对应入口。重开会保留两侧面板的打开状态及当前状态页签，并使用恢复后的记录刷新内容。技能演出、编制和战斗结果期间禁用状态入口。

「能力」「诅咒」页签各使用完整的 162×56 输入矩形（随面板缩放），按钮边缘、背景和文字区域都可点击切换。

## 能力记录

`BattleState.abilities` 记录本场战斗中我方成功发动的类型 7 技能，按首次发动顺序排列。每项包含 `skill_id`、`name`、`description`、`count`；名称和说明取自技能数据。同一技能再次发动时合并并显示「发动次数」，此数字不代表增益层数。

主动、自动、支援等技能共用 `apply_skill_commands` 完成结算时的登记入口。分段结算只在 `finished = true` 时记录一次；失败施放、敌方技能、悬停预测不会写入实际记录。新战斗清空，重开恢复战斗入口快照，因此清除重开前的发动记录。

记录展示技能的说明，不执行增益规则，也不把已发动记录当作当前增益层数。每项能力的实际效果继续由相应技能接口实现，新增效果前须先向用户确定编号基础效果或自定义技能 ID 接口。

## 周目诅咒

诅咒是原版物品卡形式的卡牌，统一在 `data/curses.txt` 定义（`scripts/curse/curse_catalog.gd` 读取），像技能、怪物一样用TXT管理：

```text
{"名称","卡面","说明",战斗显示,一次性};
{"撑着了","究极兔子锅","下场战斗开始时r  AP1消灭",1,1};
```

- 卡面是 `assets/cards/物品／<卡面>.png` 的原版物品图，不写 `.png`；说明中的小写 `r` 为换行。
- 战斗显示为 1 表示诅咒会影响战斗，显示在本页；为 0（如只影响商店的「利滚利」）则不显示。
- 一次性为 1 时，诅咒在下一场战斗开始时发动并移出部队；为 0 则永久持有。诅咒通常无法解除，没有解除接口。
- 名称唯一且不能包含 `/`，卡面必须存在，否则整份数据不投入运行。

诅咒卡固定属于主人公阵营，HP与AT都为0。获得后加入部队，在编制界面「主人公」页签的卡牌后面以物品卡显示（原版物品卡布局，圆形卡面底为原版 `下地／主人公所属` 绿色，素材 `assets/curses/card_back.png`）。诅咒卡不进入 `TroopState.available`：不能上场、拖动、锻造或出售，也不计入部队张数、阵营数值和平均AT。持有即生效，具体效果在 `scripts/curse/curse_effects.gd` 登记：`BATTLE_START` 映射战斗开始时发动的技能，`PRICE_RATES` 映射商店加价。

| 诅咒 | 效果 | 来源 |
| --- | --- | --- |
| 利滚利 | 商店所有商品价格 +20%，与邦奥佩塔之证Ａ相乘；不影响战斗 | 事件「兰斯的旧债」 |
| 撑着了 | 一次性：下场战斗开始时发动技能9818（基础效果55「AP消灭」1），开局3AP变为2AP，随后移出部队 | 事件「希露的究极兔子锅」 |

`TroopState.curses` 保存持有记录（`name`、`description`），随部队快照和周目入口存档保存，跨战斗、楼层和继续游戏保留；新周目不继承。通过 `troop.acquire_curse(名称)` 获得：名称必须在 `curses.txt` 中；已持有的诅咒不会重复获得（返回 false），但事件与控制台的 `add curse` 把这种情况视为成功，不会阻止同一选项的其他奖励。

```text
add curse 诅咒名称
```

战斗开始时（`BattleState.start`，怪物开局追加之后、第1回合开始之前）按获得顺序执行诅咒效果，并把影响战斗的诅咒快照为 `battle_curses`，所以一次性诅咒移出部队后本页仍会显示它直到战斗结束。准备阶段显示当前持有的影响战斗的诅咒。战斗重开从准备快照恢复（快照在诅咒发动之前截取），一次性诅咒会回到部队并再次发动。没有影响战斗的诅咒时显示「没有影响战斗的诅咒。」

旧存档中由旧版 `add curse 名称|说明` 写入、但不在 `curses.txt` 的记录仍保留其说明文字，卡面显示原版 `？？？` 物品图，没有效果。此处的周目诅咒与 `BattleStatusEffects.CURSE` 战斗异常独立，后者仍按原有持续回合规则结算。

`battle_state_button.gd`、`battle_state_panel.gd` 位于 `scripts/battle/`；验证脚本、截图和报告存放在工程外的 `test/battle_state_panel/` 和 `test/battle_state_side_panels/`。

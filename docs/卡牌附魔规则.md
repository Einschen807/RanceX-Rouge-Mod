# 卡牌附魔

附魔为卡牌的**一个指定技能**添加专属额外效果。每张卡牌只能附魔一次：只要其中一个技能已被附魔，这张卡就不能再附魔，即使另一个技能空着。

## 数据

附魔记录在 `data/enchantments.txt`，格式 `{名称,说明};`，说明中 `r` 表示换行。效果按名称在 `scripts/card/card_enchantments.gd`（`CardEnchantments`）分派，不占用技能的编号基础效果或自定义技能ID。新增附魔时在 TXT 加记录，并在该脚本的效果分派函数中实现。

| 名称 | 说明 | 实现 |
| --- | --- | --- |
| 先机 | AP基础消耗降低1点，但仅能在首回合释放 | 基础AP −1（最低0），AP累计与连续使用惩罚仍叠加在降低后的基础值上；战斗第2回合起该技能视为不可用，AP徽记显示为已用尽 |
| 回响 | 本场战斗首次释放时，重复释放1次 | 本场战斗中该技能第一次实际释放后，沿用战斗的“额外释放”流程再释放1次（不消耗AP、不计使用次数）；额外释放不会再次触发回响；自动发动技能同样生效 |
| 轻灵 | 该技能不再有AP惩罚 | 普通AP技能（类型1）不再有连续回合使用的 +1；AP累计类型的累计加价不受影响 |
| 伶俐 | 获得3%护盾 | 每次实际释放该技能后（在技能自身效果之后）获得3%护盾，规则与技能效果40相同；回响等额外释放不重复获得 |
| 无尽 | AP类型转化为AP累积 | 该技能视为AP累计（类型2，跨战斗保留，休息点重置卡牌状态时恢复）：本局／本场限1次的技能变为可重复使用、每次 +1 AP；普通技能则单纯变为越用越贵。强化时不再从原AP类型推导一次性限制 |

附魔可加在任何技能上（主动、自动发动等）；对不会生效的技能附魔时效果自然无效。

## 存储

附魔保存在卡牌实例设置 `TroopState.card_settings[卡名].enchantment = {"name": 附魔名, "slot": 技能槽0/1}`，随检查点、自动存档与战斗预测复制。强化／版本替换时实例设置随卡迁移，附魔留在同一技能槽。附魔不属于“重置卡牌状态”的范围。

`TroopState.enchant_card(卡名, 槽, 附魔名, 条件)` 是唯一写入口；`SkillRuntime` 通过 TroopState 注入的查询函数读取附魔，因此 AP 显示、可用判定与战斗预测共用同一规则。

## 显示

附魔名称另起一行、缩进两格，以蓝色（`CardEnchantments.BLUE`）追加在技能描述末尾，例如 `攻击(1倍)` → `攻击(1倍)` / `  回响`。部队卡牌控件、强化对比预览与战斗卡牌的技能描述都会显示；强化预览中的绿色差异标色与蓝色附魔词条可同时存在。

部队编制的技能描述视图（详情按钮第三态）中，鼠标悬停卡牌时，卡牌旁显示与遗物相同的说明框：先显示附魔（名称与说明），再按技能顺序显示该卡技能会配置的每种支援（支援名、持续回合与说明，同一支援只显示一次）。支援来自技能效果30／31以及自定义技能分派中的支援配置（`SupportCatalog.configured_by`）。多个说明框纵向排列并保持在屏幕内。

## 附魔界面与控制台

控制台 `enchantment 附魔名` 提供1次附魔。流程沿用强化界面（`CardEnchantScreen` 继承 `CardUpgradeScreen`）：进入部队编制选择列表，已附魔或没有满足条件技能的卡牌叠加原版「无法选择」遮罩，点击后弹出原版提示。选中卡牌后，左侧放大显示当前卡的技能描述面板，可悬停／点击选择要附魔的技能（不满足条件的技能面板变暗不可选，只有一个可选技能时自动选中）；右侧实时预览附魔后的蓝字效果，底部显示附魔说明，「确认附魔」后播放蓝色光环与光点演出并生效。右键／Esc 返回规则与强化相同；未使用附魔次数时退出需确认。

## 条件附魔（事件扩展接口）

事件可能只允许附魔满足条件的技能（例如“为一个AP为0的技能附魔重放”）。条件以字典传入：`BattleManager.launch_enchant(附魔名, 部队, 条件)` → `CardEnchantScreen.requirement` → `CardEnchantments.requirement_met(技能, 条件)`。目前支持的键：

- `"ap"`：主动技能的基础AP必须等于该值；
- `"action"`：技能行动类型必须等于该值。

条件为空时接受所有技能。新的条件类型在 `requirement_met` 中扩展；事件指令尚未接入，届时只需把事件参数解析为该字典。

验证脚本与截图位于工程外 `test/enchantment_20261028/`。
